# KB_01: Storytelling Frameworks - Elite Executive Communication

## VISÃO GERAL

Este Knowledge Base consolida as metodologias fundamentais de narrativa executiva utilizadas pelas top-tier consulting firms globalmente. Dominar estes frameworks é a diferença entre uma apresentação que informa e uma que transforma decisões.

**Frameworks cobertos:**
- Pyramid Principle (Barbara Minto / McKinsey)
- SCQA Framework (Situation-Complication-Question-Answer)
- MECE Methodology (Mutually Exclusive, Collectively Exhaustive)
- Action Titles Mastery
- Vertical & Horizontal Flow
- Executive Summary Construction
- Rule of Three
- Ordering Logic (4 tipos)

## 1. PYRAMID PRINCIPLE (Barbara Minto)

### 1.1. Origem e Fundamentos Teóricos

**Desenvolvido por:** Barbara Minto, primeira consultora mulher da McKinsey & Company (1973)

**Base científica:** Pesquisa em cognição humana demonstra que o cérebro:
- Automaticamente agrupa informações em estruturas hierárquicas
- Processa mais eficientemente quando conclusão vem primeiro (top-down)
- Retém melhor quando ideias são agrupadas em conjuntos de 3-7 (ideal: 3-5)
- Prefere padrões lógicos reconhecíveis

**Aplicação:** Qualquer comunicação de alta densidade informacional para audiência executiva.

### 1.2. Estrutura da Pirâmide

```
                    [RESPOSTA/CONCLUSÃO PRINCIPAL]
                    "O que você quer que eu faça/saiba?"
                                |
            ┌───────────────────┼───────────────────┐
            |                   |                   |
      [ARGUMENTO 1]       [ARGUMENTO 2]       [ARGUMENTO 3]
       "Por que?"          "Por que?"          "Por que?"
            |                   |                   |
        ┌───┼───┐           ┌───┼───┐           ┌───┼───┐
        |   |   |           |   |   |           |   |   |
     [DADOS E EVIDÊNCIAS]  [DADOS E EVIDÊNCIAS]  [DADOS E EVIDÊNCIAS]
       "Como você sabe?"    "Como você sabe?"    "Como você sabe?"
```

**Regras Fundamentais:**

1. **Ideias em qualquer nível sempre resumem as ideias agrupadas abaixo delas**
   - Nível superior = síntese do nível inferior
   - Se você remover o nível superior, deve ser capaz de reconstruí-lo apenas olhando o nível abaixo

2. **Ideias em cada agrupamento devem ser do mesmo tipo lógico**
   - Não misturar problemas com soluções
   - Não misturar causas com efeitos
   - Não misturar argumentos dedutivos com comparativos

3. **Ideias em cada agrupamento devem seguir ordem lógica**
   - Dedutiva, cronológica, estrutural ou comparativa (ver seção 7)
   - Nunca ordem aleatória ou "como veio à cabeça"

### 1.3. Aplicação em Slides (Vertical Flow)

**Anatomia de um slide seguindo Pyramid:**

```
┌─────────────────────────────────────────────────┐
│ TÍTULO = TOPO DA PIRÂMIDE (conclusão/insight)   │ ← Nível 1
├─────────────────────────────────────────────────┤
│                                                 │
│   [VISUAL PRINCIPAL]                            │ ← Nível 2
│   Gráfico/Tabela mostrando 3-4 argumentos       │   (argumentos)
│                                                 │
│   ┌─────────┐  ┌─────────┐  ┌─────────┐       │
│   │Evidência│  │Evidência│  │Evidência│       │ ← Nível 3
│   │    1    │  │    2    │  │    3    │       │   (dados)
│   └─────────┘  └─────────┘  └─────────┘       │
│                                                 │
├─────────────────────────────────────────────────┤
│ FONTE = BASE DA PIRÂMIDE (credibilidade)        │ ← Fundação
└─────────────────────────────────────────────────┘
```

**Exemplo Concreto:**

**Nível 1 (Título):**
"Mercado brasileiro de IA crescerá 45% ao ano até 2027, superando média global"

**Nível 2 (Argumentos no gráfico):**
- Linha 1: Crescimento Brasil (visual)
- Linha 2: Crescimento Global (visual)
- Gap entre linhas (evidência do "superando")

**Nível 3 (Dados - tabela de suporte):**
- 2024: R$ 9.2bi
- 2025E: R$ 13.4bi
- 2026E: R$ 17.8bi
- 2027E: R$ 23.1bi
- CAGR calculado: 45%

**Fundação (Fonte):**
"IDC Brasil, McKinsey Global AI Survey, análise da equipe"

### 1.4. Aplicação em Decks (Horizontal Flow)

**Estrutura de apresentação completa:**

**Executive Summary = Topo da Pirâmide**
- Todas as conclusões principais (3-5 máximo)
- Se apresentação for cancelada, este slide funciona standalone

**Body Slides = Meio da Pirâmide**
- Cada seção desenvolve UM dos argumentos do Executive Summary
- Dentro da seção, slides individuais são evidências

**Appendix = Base da Pirâmide**
- Dados brutos
- Metodologia detalhada
- Cálculos completos
- Análises secundárias

**Exemplo de mapeamento:**

```
Executive Summary (Slide 2):
"Empresa deve priorizar canal B2B sobre B2C para maximizar ROI em 24 meses"
├─ Por quê? 3 razões:
   ├─ 1. Margem B2B é 3× maior
   ├─ 2. Ciclo de vendas B2B é 40% mais curto
   └─ 3. Concorrência B2B é fragmentada

Body - Seção 1: Análise de Margens (Slides 4-7)
├─ Slide 4: "Margem B2B média é 42% vs. 14% em B2C"
├─ Slide 5: "Estrutura de custos B2B favorece economia de escala"
├─ Slide 6: "Projeção: EBITDA B2B atinge 35% em 2027"
└─ Slide 7: "Sensibilidade: ROI B2B superior mesmo em cenário pessimista"

Body - Seção 2: Análise de Ciclo de Vendas (Slides 8-10)
├─ Slide 8: "Ciclo médio B2B é 45 dias vs. 75 dias B2C neste segmento"
├─ Slide 9: "Drivers de velocidade: decisor único em B2B, comitê em B2C"
└─ Slide 10: "Impacto em cash flow: payback 8 meses mais rápido"

Body - Seção 3: Análise Competitiva (Slides 11-13)
├─ Slide 11: "Mercado B2B tem 20 players vs. 3 dominantes em B2C"
├─ Slide 12: "Market share alcançável: 15% em B2B vs. 3% em B2C"
└─ Slide 13: "Barreiras de entrada são menores em B2B"

Recommendations (Slides 14-16)
└─ Plano de ação para pivô B2B

Appendix (Slides 17-25)
└─ Dados detalhados, metodologia, sensibilidades
```

### 1.5. Teste de Qualidade - Vertical Consistency

**Como aplicar:**

1. Liste APENAS os títulos de todos os slides (ignore conteúdo)
2. Leia em voz alta como se fosse uma conversa de 2 minutos
3. Pergunte: "A história está completa? Argumentos são claros?"

**Se a resposta for NÃO, a estrutura precisa revisão.**

**Exemplo de estrutura RUIM (falha no teste):**

1. "Introdução ao mercado de IA"
2. "Definição de IA generativa"
3. "Histórico da empresa"
4. "Dados de crescimento"
5. "Análise competitiva"

**Problema:** Títulos descritivos, não comunicam insights. Não conta história.

**Exemplo de estrutura BOA (passa no teste):**

1. "Brasil deve investir $50M em IA generativa para capturar 15% de market share até 2027"
2. "Mercado brasileiro de IA generativa crescerá 60% ao ano, 2× mais rápido que global"
3. "Empresa está bem posicionada em tecnologia mas ausente em go-to-market"
4. "Window de oportunidade fecha em 18 meses devido a entrada de big techs"
5. "Investimento de $50M em sales/marketing gera ROI de 3.2× em 36 meses"

**Resultado:** História completa. Executivo entende problema, oportunidade, urgência e solução.

## 2. SCQA FRAMEWORK

### 2.1. Definição

**SCQA** = Situation - Complication - Question - Answer

Estrutura narrativa que cria tensão e resolve, mantendo audiência engajada.

**Origem:** Desenvolvido por Barbara Minto como extensão do Pyramid Principle para criar narrativas persuasivas.

### 2.2. Os 4 Componentes

**S = SITUATION (Contexto)**

**Objetivo:** Estabelecer baseline, status quo, realidade compartilhada

**Características:**
- Tom: Neutro, factual, não controverso
- Tempo verbal: Passado ou presente
- Duração: 10-20% da apresentação
- Reação desejada da audiência: "Concordo, é assim mesmo"

**Exemplo:**
"Empresa XYZ opera no mercado de software B2B há 15 anos, com receita estável de $200M/ano e margem EBITDA de 25%, alinhada com peers do setor."

**C = COMPLICATION (Complicação)**

**Objetivo:** Introduzir mudança, problema, ameaça, oportunidade

**Características:**
- Tom: Urgente, preocupante, ou excitante (se oportunidade)
- Tempo verbal: Presente ou futuro próximo
- Duração: 5-10% da apresentação
- Reação desejada: "Isso é um problema/oportunidade que precisa de ação"

**Exemplo:**
"Novo regulamento europeu (GDPR 2.0) entrará em vigor em 18 meses, exigindo re-arquitetura completa de 60% dos produtos atuais. Não conformidade resultaria em multas de até €50M e perda de licença para operar na EU, que representa 40% da receita."

**Q = QUESTION (Pergunta)**

**Objetivo:** Articular a questão central que a apresentação responderá

**Características:**
- Geralmente IMPLÍCITA (não precisa de slide dedicado)
- Aparece como título de slide de Agenda ou está subentendida
- Audiência deve formular mentalmente antes de você responder

**Exemplo (implícito):**
"Como devemos responder a este regulamento para proteger receita e manter liderança?"

**OU (explícito em slide de Agenda):**
"Agenda: (1) Avaliar impacto do regulamento, (2) Analisar opções de resposta, (3) Recomendar plano de ação"

**A = ANSWER (Resposta)**

**Objetivo:** Fornecer solução/recomendação estruturada

**Características:**
- Tom: Confiante, baseado em dados, acionável
- Duração: 70-80% da apresentação
- Estrutura: Pyramid Principle (conclusão → argumentos → evidências)

**Exemplo:**
"Recomendamos investimento de $30M em 12 meses para re-arquitetura de plataforma, que: (1) garante conformidade total, (2) cria vantagem competitiva via privacy-by-design, (3) gera ROI de 2.1× em 36 meses através de premium pricing."

### 2.3. Variações de Sequência

**SCQA Clássico (mais comum):**
S → C → Q → A

Use quando: Audiência conhece situação, você precisa introduzir novo problema/oportunidade

**QSCA (começar com pergunta):**
Q → S → C → A

Use quando: Audiência já sabe do problema, quer solução rápida (apresentações follow-up)

**ACSQ (começar com resposta):**
A → C → S → Q

Use quando: Audiência impaciente (C-level), quer bottom line primeiro, depois justificativa

**CSA (omitir Q explícita):**
C → S → A

Use quando: Pergunta é óbvia dado o contexto, não precisa articular

### 2.4. Mapeamento SCQA em Slides

**Exemplo de deck de 30 slides:**

**Slides 1-3: Introdução (não-SCQA)**
- Slide 1: Title
- Slide 2: Executive Summary
- Slide 3: Agenda

**Slides 4-7: SITUATION (13% do deck)**
- Slide 4: "Empresa XYZ possui posição consolidada em software B2B europeu"
- Slide 5: "Receita cresceu 12% ao ano nos últimos 5 anos, acima do mercado"
- Slide 6: "Base de 450 clientes enterprise com NPS de 62 (líder de setor)"
- Slide 7: "Margem EBITDA de 25% se manteve estável desde 2019"

**Slides 8-10: COMPLICATION (10% do deck)**
- Slide 8: "GDPR 2.0 exigirá re-arquitetura de 60% dos produtos até junho 2026"
- Slide 9: "Não conformidade implicará multas de €50M e possível perda de licença EU"
- Slide 10: "Window de ação é apenas 18 meses - competidores já iniciaram adaptação"

**Slide 11: QUESTION (implícita na agenda, 3% do deck)**
- "Agenda de análise: Impacto → Opções → Recomendação"

**Slides 12-28: ANSWER (70% do deck)**

*Sub-seção A: Análise de Impacto*
- Slides 12-16: Detalhamento técnico, financeiro, timing

*Sub-seção B: Opções Avaliadas*
- Slides 17-21: Opção 1 (minimal compliance), Opção 2 (full replatform), Opção 3 (hybrid)

*Sub-seção C: Recomendação*
- Slides 22-28: Opção 2 recomendada, business case, roadmap, risks

**Slides 29-30: Conclusão**
- Slide 29: Next Steps
- Slide 30: Q&A

## 3. MECE METHODOLOGY

### 3.1. Definição

**MECE** = Mutually Exclusive, Collectively Exhaustive

**Mutually Exclusive (ME):** Categorias não se sobrepõem
**Collectively Exhaustive (CE):** Categorias cobrem todo o universo relevante

**Importância:** Framework fundamental para estruturar problemas sem ambiguidade.

### 3.2. Mutually Exclusive (sem overlap)

**RUIM (não ME):**
Segmentar mercado em:
- Empresas grandes (>1000 funcionários)
- Empresas de tecnologia
- Empresas multinacionais

**Problema:** Google é grande E tecnologia E multinacional. Onde classificar?

**BOM (ME):**
Segmentar mercado em:
- Empresas 1-50 funcionários (Small)
- Empresas 51-500 funcionários (Medium)
- Empresas 501+ funcionários (Large)

**Solução:** Categorias são mutuamente exclusivas baseadas em critério único (# funcionários)

### 3.3. Collectively Exhaustive (cobrir tudo)

**RUIM (não CE):**
Analisar drivers de crescimento:
- Aquisição de novos clientes
- Upsell para clientes existentes

**Problema:** E quanto a expansão geográfica? Novos produtos? M&A? Categorias não exaurem possibilidades.

**BOM (CE):**
Analisar drivers de crescimento:
- Crescimento orgânico
  - Mesmos produtos, mesmos mercados (penetração)
  - Mesmos produtos, novos mercados (expansão geográfica)
  - Novos produtos, mesmos mercados (inovação)
  - Novos produtos, novos mercados (diversificação)
- Crescimento inorgânico (M&A)

**Solução:** Framework cobre todas as possibilidades (Ansoff Matrix adaptado)

### 3.4. Aplicação em Slides

**Teste MECE para cada slide:**

**Slide sobre "Drivers de crescimento do mercado de IA":**

**Tentativa 1 (FALHA MECE):**
1. Investimento corporativo
2. Avanços tecnológicos
3. Casos de uso em saúde
4. Regulação favorável

**Problema:** "Casos de uso em saúde" está em nível diferente dos outros (específico vs. macro)

**Tentativa 2 (PASSA MECE):**
1. Fatores de demanda (pull)
   - Adoção corporativa acelerada
   - Novos casos de uso em indústrias-chave
2. Fatores de oferta (push)
   - Avanços em modelos (GPT-4, etc.)
   - Redução de custo computacional
3. Fatores regulatórios/ambientais
   - Regulação favorável
   - Investimento governamental

**Solução:** Categorias são ME (demanda/oferta/contexto) e CE (cobre todos drivers)

### 3.5. MECE em Estrutura de Apresentação

**Teste: Títulos das seções principais devem ser MECE**

**Exemplo - Apresentação sobre "Estratégia de Go-to-Market":**

**RUIM:**
1. Análise de mercado
2. Análise competitiva
3. Nosso posicionamento
4. Estratégia de pricing
5. Canais de distribuição

**Problema:** Não é ME (posicionamento overlap com competitiva) nem CE (falta produto, marketing, etc.)

**BOM:**
1. Onde competir (mercado, segmentos)
2. Como vencer (proposta de valor, diferenciação)
3. Capabilities necessárias (produto, operações, people)
4. Go-to-market (pricing, canais, marketing)
5. Plano de implementação (roadmap, investimento, governance)

**Solução:** Segue lógica Strategy → Capabilities → Execution, sem overlaps, cobrindo tudo.

## 4. ACTION TITLES MASTERY

### 4.1. Princípio Fundamental

**Action Title** = Título que comunica insight/conclusão, não descreve conteúdo

**Regra de ouro:** Executivo deve saber "So What?" apenas lendo título, sem ver slide.

### 4.2. Fórmula de Construção

```
[O QUE ACONTECEU/ESTÁ ACONTECENDO] + [POR QUE IMPORTA] + [IMPLICAÇÃO IMPLÍCITA]
```

**Componentes:**

1. **O que:** Fato específico, dado concreto, mudança observada
2. **Por que:** Contexto, significância, magnitude
3. **Implicação:** O que fazer a respeito (pode ser implícito)

**Exemplo construído:**

1. **O que:** "Market share caiu 15%"
2. **+ Por que:** "devido a entrada de 3 novos competidores low-cost"
3. **+ Implicação:** [implícito: precisamos responder]

**Resultado:** "Market share caiu 15% devido a 3 novos competidores low-cost"

### 4.3. Transformações Antes/Depois

**Categoria: Data Slide (Quantitativo)**

| ❌ Título Descritivo | ✅ Action Title |
|---------------------|----------------|
| Receita por região | Região Sul superou Norte pela primeira vez, impulsionada por expansão B2B (+35%) |
| Análise de churn | Taxa de churn dobrou para 8% no Q3, concentrada em clientes SMB sem success manager |
| NPS ao longo do tempo | NPS caiu 12 pontos em 6 meses, refletindo problemas de onboarding não resolvidos |
| Market share | Perdemos 5pp de market share para Competidor X, que adotou modelo freemium |

**Categoria: Qualitative Slide (Frameworks, Processos)**

| ❌ Título Descritivo | ✅ Action Title |
|---------------------|----------------|
| Processo de aprovação atual | Processo de aprovação causa 12 dias de atraso médio, exigindo redesenho com automação |
| Estrutura organizacional | Estrutura atual cria silos que impedem colaboração cross-funcional necessária |
| Jornada do cliente | Cliente enfrenta 8 pontos de fricção entre onboarding e first value, vs. 3 em benchmark |
| Cadeia de valor | Atividades de suporte consomem 60% do OpEx mas geram <10% de diferenciação percebida |

**Categoria: Recommendation Slide**

| ❌ Título Descritivo | ✅ Action Title |
|---------------------|----------------|
| Opções estratégicas | Opção B (parceria estratégica) entrega ROI 2.5× maior que build próprio com 50% menos risco |
| Análise de cenários | Cenário otimista requer apenas 15% de aumento em conversão vs. 100% em cenário base |
| Próximos passos | Implementação em 3 ondas (Pilots Q1 → Scale Q2-Q3 → Optimize Q4) minimiza disruption |

**Categoria: Benchmark/Comparison**

| ❌ Título Descritivo | ✅ Action Title |
|---------------------|----------------|
| Comparação com peers | Estamos 40% abaixo do benchmark em NPS mas 25% acima em eficiência operacional |
| Análise competitiva | Competidor A lidera em features (85 vs. 62), mas nossa usabilidade é 2× superior (SUS score) |
| Best practices setoriais | Líderes de setor investem 18% de receita em P&D vs. nossos 8%, explicando gap de inovação |

### 4.4. Erros Comuns e Como Corrigir

**ERRO 1: Título genérico**
❌ "Resultados do trimestre"
✅ "Receita Q3 superou guidance em 12%, impulsionada por enterprise segment"

**ERRO 2: Título muito longo/complexo**
❌ "Análise detalhada das variações de receita mês a mês por região geográfica incluindo breakdown por produto e comparação com forecasts anteriores demonstrando..."
✅ "Receita cresceu 15% em América Latina mas caiu 8% em Europa, refletindo dinâmicas regulatórias"
(Se necessário, detalhes vão no conteúdo)

**ERRO 3: Título que requer ver slide para entender**
❌ "Esta tabela mostra dados importantes"
✅ "Custo de aquisição (CAC) aumentou 30% enquanto LTV permaneceu estável, reduzindo payback para 18 meses"

**ERRO 4: Pergunta como título**
❌ "Como devemos responder ao competidor X?"
✅ "Resposta ao competidor X deve focar em diferenciação de produto vs. guerra de preços"
(Título deve responder, não perguntar)

**ERRO 5: Título neutro quando há insight forte**
❌ "Análise de custos operacionais"
✅ "40% dos custos operacionais são evitáveis via automação, liberando $8M anuais"

### 4.5. Técnicas Avançadas

**Técnica 1: Usar números específicos**
- Vago: "Crescimento significativo"
- Específico: "Crescimento de 47%"

**Técnica 2: Adicionar contexto comparativo**
- Sem contexto: "Receita de $50M"
- Com contexto: "Receita de $50M, 3× acima do ano anterior"

**Técnica 3: Explicitar causa quando conhecida**
- Sem causa: "Market share caiu"
- Com causa: "Market share caiu devido a atraso de 6 meses no lançamento de produto"

**Técnica 4: Antecipar "So What?"**
- Sem implicação: "NPS é 45"
- Com implicação: "NPS de 45 está em zona de risco de churn (benchmark: 60+)"

**Técnica 5: Usar contraste para ênfase**
- Linear: "Custos aumentaram 20%"
- Contraste: "Custos aumentaram 20% enquanto receita cresceu apenas 5%, comprimindo margem"

## 5. VERTICAL & HORIZONTAL FLOW

### 5.1. Vertical Flow (dentro de um slide)

**Princípio:** O olho deve ser guiado do insight (topo) para evidências (base)

**Ordem de leitura desejada:**

1. **Título** (2-3 segundos) → Entender mensagem principal
2. **Visual principal** (5-10 segundos) → Ver evidência visual
3. **Callouts/Annotations** (3-5 segundos) → Insights específicos
4. **Dados de suporte** (5-10 segundos) → Detalhes numéricos
5. **Fonte** (1-2 segundos) → Validar credibilidade

**Como garantir:**
- **Hierarquia de tamanho:** Título maior (28pt) → Labels médios (14pt) → Fonte menor (9pt)
- **Hierarquia de cor:** Título em cor forte (#003B5C) → Conteúdo em preto (#000000) → Fonte em cinza (#6E6E6E)
- **Hierarquia de posição:** Topo = principal, Meio = argumentos, Base = suporte
- **Contraste:** Elementos importantes têm maior contraste com fundo

**Teste:** Mostre slide para alguém por 10 segundos. Pergunte "Qual a mensagem?"
- Se responderem corretamente = vertical flow funciona
- Se ficarem confusos = redesign necessário

### 5.2. Horizontal Flow (entre slides)

**Princípio:** Cada slide deve conectar logicamente ao anterior e preparar o próximo

**Técnicas de Conexão:**

**1. Progressão Lógica:**
- Slide N: "Problema identificado: custo muito alto"
- Slide N+1: "Análise de causas raiz do custo elevado"
- Slide N+2: "Três iniciativas para reduzir custo"

**2. Zoom In/Zoom Out:**
- Slide N: "Receita cresceu 20% (visão geral)"
- Slide N+1: "Crescimento impulsionado por região Sul (zoom in na região)"
- Slide N+2: "Região Sul cresceu via expansão de clientes enterprise (zoom in no segmento)"

**3. Construção Cumulativa:**
- Slide N: "Driver 1: Investimento corporativo"
- Slide N+1: "Driver 2: Regulação favorável"
- Slide N+2: "Driver 3: Escassez de talent"
- Slide N+3: "Combinação dos 3 drivers explica 80% do crescimento"

**4. Contraste/Comparação:**
- Slide N: "Opção A: Build próprio - $20M, 18 meses"
- Slide N+1: "Opção B: Parceria - $8M, 9 meses"
- Slide N+2: "Comparação: Opção B entrega ROI 2× maior"

**Frases de Transição (em speaker notes):**
- "Agora que vimos o problema, vamos analisar causas"
- "Detalhando o driver mais importante..."
- "Passando de análise para recomendações..."
- "Para implementar esta estratégia, são necessários 3 capabilities"

### 5.3. Teste de Flow Completo

**Vertical Flow Test (por slide):**
1. Cubra tudo exceto título
2. Leia título
3. Descubra slide
4. Pergunte: "O conteúdo suporta/prova o título?"

**Horizontal Flow Test (deck completo):**
1. Imprima todos os slides em miniatura
2. Organize em sequência na mesa
3. Olhe de cima (bird's eye view)
4. Pergunte: "A progressão faz sentido? Há saltos lógicos?"

## 6. EXECUTIVE SUMMARY CONSTRUCTION

### 6.1. Propósito

Executive Summary é o slide mais importante da apresentação.

**Deve:**
- Comunicar TODAS as mensagens principais em 1 slide
- Funcionar standalone se apresentação for cancelada
- Ser compreensível em 60 segundos
- Motivar audiência a ouvir o restante (ou aprovar sem ouvir)

### 6.2. Estrutura Ideal

**Componente 1: Título**
- Deve ser a mensagem #1 (conclusão principal)
- Formato action title
- Ex: "Empresa deve investir $50M em IA para capturar market share antes de big techs"

**Componente 2: 3-5 Key Messages**
- Cada um é um argumento de suporte da mensagem principal
- Estruturados em caixas visuais distintas
- Ícone ou número para cada um
- 1-2 linhas por mensagem

**Componente 3: Visual (opcional)**
- Gráfico síntese ou diagrama conceitual
- Se incluir, deve ser auto-explicativo

**Componente 4: Call to Action (opcional)**
- "Seeking approval for $50M investment"
- "Requesting Board decision by end of Q1"

### 6.3. Layouts Efetivos

**Layout A: 3 Caixas Horizontais**
```
┌─────────────────────────────────────────────────┐
│ TÍTULO PRINCIPAL                                │
├───────────────┬───────────────┬─────────────────┤
│  [Icon/1]     │  [Icon/2]     │  [Icon/3]       │
│               │               │                 │
│  Key Message  │  Key Message  │  Key Message    │
│  1            │  2            │  3              │
│  (2-3 linhas) │  (2-3 linhas) │  (2-3 linhas)   │
└───────────────┴───────────────┴─────────────────┘
```

**Quando usar:** Mensagens são de igual importância

**Layout B: Pirâmide Visual**
```
┌─────────────────────────────────────────────────┐
│ TÍTULO PRINCIPAL                                │
├─────────────────────────────────────────────────┤
│              [Key Message 1]                    │
│          (Mais importante, maior)               │
│                                                 │
│   [Key Message 2]      [Key Message 3]          │
│   (Secundários, menores)                        │
│                                                 │
│   [Supporting points]                           │
└─────────────────────────────────────────────────┘
```

**Quando usar:** Há uma mensagem claramente dominante

**Layout C: Gráfico + Insights**
```
┌─────────────────────────────────────────────────┐
│ TÍTULO PRINCIPAL                                │
├──────────────────────┬──────────────────────────┤
│                      │  KEY INSIGHTS            │
│  [Gráfico Síntese]   │  • Insight 1             │
│  (ex: crescimento)   │  • Insight 2             │
│                      │  • Insight 3             │
│                      │  • Insight 4             │
│                      │  • Insight 5             │
└──────────────────────┴──────────────────────────┘
```

**Quando usar:** Há um visual poderoso que conta história sozinho

### 6.4. Regras de Conteúdo

**Regra 1: Máximo 5 mensagens**
- Ideal: 3 mensagens
- Aceitável: 4-5 mensagens
- Nunca: 6+ mensagens (cognitive overload)

**Regra 2: Cada mensagem em 1-2 linhas**
- Não parágrafos
- Bullet points ou boxes

**Regra 3: Hierarquia clara**
- Mensagem principal (título) > Sub-mensagens (bullets)

**Regra 4: Auto-suficiência**
- Não referenciar "como veremos no slide X"
- Deve funcionar isoladamente

**Regra 5: Ação clara**
- O que você quer que a audiência faça/aprove/saiba?

### 6.5. Exemplos Completos

**Exemplo 1: Decisão de Investimento**

**Título:**
"Recomendamos investimento de $30M em plataforma de IA para transformar customer experience e gerar $120M em valor em 3 anos"

**Key Messages:**
1. **Oportunidade**: Mercado de CX AI crescerá 45% ao ano, janela de liderança fecha em 18 meses
2. **Capabilities**: Temos tecnologia e talent necessários, mas falta plataforma enterprise-grade
3. **Business Case**: Investimento de $30M gera ROI de 4× via redução de custo ($40M) e revenue uplift ($80M)
4. **Risco mitigado**: Abordagem phased (Pilot → Scale → Optimize) permite validação antes de full commitment

**Exemplo 2: Análise Estratégica**

**Título:**
"Empresa deve pivotar de B2C para B2B para atingir meta de $500M revenue até 2027"

**Key Messages:**
1. **B2C está saturado**: Crescimento caiu de 25% para 8% ao ano, CAC aumentou 3×
2. **B2B é oportunidade inexplorada**: Mercado de $2B crescendo 30% ao ano, apenas 2 competidores sérios
3. **Temos right to win**: Tecnologia atual serve B2B com adaptações mínimas ($5M investment)
4. **Timing é crítico**: Big techs ainda não entraram, mas anunciaram intenção para 2025

## 7. ORDERING LOGIC (4 Tipos)

### 7.1. Quando aplicar cada tipo

**Regra geral:** Escolha UMA lógica dominante por seção. Não misturar.

### 7.2. Tipo 1: DEDUTIVA (Silogismo)

**Estrutura:**
- Premissa maior (universal)
- Premissa menor (específica)
- Conclusão (necessária)

**Exemplo:**
1. "Mercados em crescimento >30% ao ano requerem investimento agressivo para captura de share" (premissa maior)
2. "Mercado brasileiro de IA está crescendo 45% ao ano" (premissa menor)
3. "Portanto, devemos investir agressivamente em IA no Brasil" (conclusão)

**Quando usar:**
- Argumentos lógicos de causa-efeito
- Quando conclusão é inevitável dados os fatos
- Audiência analítica/racional (finance, strategy)

### 7.3. Tipo 2: CRONOLÓGICA (Temporal)

**Estrutura:**
- Primeiro → Segundo → Terceiro (sequência temporal)
- Passado → Presente → Futuro

**Exemplo 1 (sequência de eventos):**
1. "2020-2021: Pandemia acelerou digitalização, criando demanda inicial"
2. "2022-2023: Investimento corporativo em IA triplicou"
3. "2024-2025: Regulação criou ambiente favorável"
4. "2026-2027: Escala de mercado atrai big techs, janela de oportunidade fecha"

**Exemplo 2 (processo):**
1. "Fase 1 (Q1 2025): Pilot com 3 clientes enterprise"
2. "Fase 2 (Q2-Q3): Scale para 20 clientes baseado em learnings"
3. "Fase 3 (Q4): Optimize e prepare para 2026 mass market"

**Quando usar:**
- Roadmaps, timelines, implementation plans
- Historical analysis
- Process flows

### 7.4. Tipo 3: ESTRUTURAL (Espacial/Hierárquico)

**Estrutura:**
- Dividir por localização geográfica, camadas organizacionais, componentes de sistema

**Exemplo 1 (geográfico):**
1. "América do Norte: Mercado maduro, crescimento 12%"
2. "Europa: Crescimento 18%, impulsionado por regulação"
3. "Ásia: Crescimento 35%, liderado por China e Índia"
4. "América Latina: Crescimento 45%, oportunidade inexplorada"

**Exemplo 2 (hierárquico - organização):**
1. "Nível Corporate: Definir estratégia e alocar capital"
2. "Nível Business Unit: Executar em seus mercados"
3. "Nível Funcional: Desenvolver capabilities (tech, sales, ops)"
4. "Nível Frontline: Implementar no dia-a-dia com clientes"

**Exemplo 3 (componentes de sistema):**
1. "Layer 1 - Infraestrutura: Cloud, data storage, security"
2. "Layer 2 - Platform: APIs, integration, orchestration"
3. "Layer 3 - Applications: User-facing tools e dashboards"
4. "Layer 4 - Experience: UI/UX e customer touchpoints"

**Quando usar:**
- Análise por segmento/região
- Org design, operating models
- Technical architecture

### 7.5. Tipo 4: COMPARATIVA (Por Grau/Ranking)

**Estrutura:**
- Mais importante → Menos importante
- Maior impacto → Menor impacto
- Melhor → Pior

**Exemplo 1 (priorização):**
1. "Iniciativa A: ROI de 5×, payback 6 meses - **PRIORIDADE 1**"
2. "Iniciativa B: ROI de 3×, payback 12 meses - **PRIORIDADE 2**"
3. "Iniciativa C: ROI de 1.5×, payback 24 meses - **PRIORIDADE 3**"

**Exemplo 2 (magnitude):**
1. "Driver #1: Pricing (contribui 60% do upside potencial)"
2. "Driver #2: Volume (contribui 30%)"
3. "Driver #3: Mix (contribui 10%)"

**Exemplo 3 (ranking competitivo):**
1. "Competidor A: Líder (40% market share, score 9.2/10)"
2. "Nossa empresa: Challenger (25% share, score 7.8/10)"
3. "Competidor B: Follower (20% share, score 6.5/10)"
4. "Competidor C: Niche player (15% share, score 5.2/10)"

**Quando usar:**
- Priorização de iniciativas
- Ranking de opções
- Pareto analysis (80/20)
- Competitive positioning

## 8. RULE OF THREE

### 8.1. Fundamento Psicológico

**Pesquisa em cognition:**
- Cérebro processa grupos de 3 mais facilmente que 2 ou 4+
- Listas de 3 são mais memoráveis (ex: "Vida, liberdade, busca da felicidade")
- Padrão de 3 cria sensação de completude

**Aplicação:** Sempre que possível, agrupar em 3s.

### 8.2. Aplicações

**Nível 1: Mensagens principais de apresentação**
- 3 pilares principais (não 2, não 5)
- Se tiver 4-5, agrupar em 3 categorias

**Nível 2: Bullets por slide**
- Máximo 3 bullets de nível 1
- Se precisar de sub-bullets, máximo 3 por bullet

**Nível 3: Exemplos/Evidências**
- Dar 3 exemplos (não 1, não 7)

**Exceções aceitáveis:**
- 2 itens: OK se forem dicotomia natural (Before/After, Option A vs B)
- 4-5 itens: OK se forem lista exaustiva necessária (ex: 5 forças de Porter)

### 8.3. Quando você tem 6 argumentos

**Problema:** 6 argumentos principais identificados

**Soluções:**

**Opção A: Agrupar em 3 categorias**
- Categoria 1: Fatores de mercado (arg 1, arg 2)
- Categoria 2: Fatores internos (arg 3, arg 4)
- Categoria 3: Fatores competitivos (arg 5, arg 6)

**Opção B: Priorizar top 3**
- Manter 3 principais
- Mover outros 3 para Appendix ou mencionar brevemente

**Opção C: 3 + 3**
- 3 principais (slides dedicados)
- 3 secundários (1 slide consolidado: "Outros fatores relevantes")

## 9. CHECKLIST DE QUALIDADE NARRATIVA

Use para validar qualquer apresentação:

**Pyramid Principle:**
- [ ] Cada nível resume o nível abaixo?
- [ ] Ideias de mesmo nível são do mesmo tipo lógico?
- [ ] Há ordem lógica clara em cada agrupamento?

**SCQA:**
- [ ] Situation estabelece baseline compartilhado?
- [ ] Complication cria tensão/urgência?
- [ ] Question está articulada (explícita ou implícita)?
- [ ] Answer resolve de forma estruturada?

**MECE:**
- [ ] Categorias são mutuamente exclusivas (sem overlap)?
- [ ] Categorias são coletivamente exaustivas (cobrem tudo relevante)?

**Action Titles:**
- [ ] Todo título comunica insight vs. descreve conteúdo?
- [ ] "So What?" está respondido apenas no título?
- [ ] Títulos específicos (números, causas, contexto)?

**Flow:**
- [ ] Vertical flow: título → visual → dados funciona?
- [ ] Horizontal flow: transições lógicas entre slides?
- [ ] Teste de 2 minutos: títulos contam história completa?

**Executive Summary:**
- [ ] Funciona standalone (sem resto da apresentação)?
- [ ] 3-5 mensagens principais (não mais)?
- [ ] Compreensível em 60 segundos?
- [ ] Ação/decisão desejada está clara?

**Rule of Three:**
- [ ] Mensagens principais agrupadas em 3s quando possível?
- [ ] Slides não têm >3 bullets de nível 1?

**Ordering Logic:**
- [ ] Cada seção segue UMA lógica clara (dedutiva/cronológica/estrutural/comparativa)?
- [ ] Ordenação faz sentido e é justificável?
