**Important correction:** earlier analysis and chat output claimed "400+ sessions in activation-log.jsonl". The actual number is **42 events** in activation-log.jsonl. The 403 figure is session archives in `.synapse/sessions/`. Both numbers are real observability data but they measure different things. When discussing `.synapse` as observability, cite the correct metric:
- For **activation events** (skill/agent invoked): activation-log.jsonl has 42 entries
- For **full session captures** (multi-turn conversations with metadata): sessions/ has 403 entries
- For **per-call engine telemetry** (model, tokens, latency): engine-usage.jsonl has 344 entries

## Things That Were Wrong (Non-Obvious)

Things I learned while verifying that were actually misleading in the originals:
1. **"473 agents" sounded impressive but masked a worse problem** — auto-generated stubs with zero specialization. The post-cleanup 57 is **healthier**, not a regression.
2. **"2.65M YAML LOC" was inflated by node_modules** — the real SOT content is ~500K, which is still impressive but not "dark matter" scale.
3. **"1,000x more governance than OpenClaw"** — hyperbolic. Real ratio is ~8x, still substantial.
4. **"400+ sessions in activation-log"** — I said this in chat multiple times. The real number in activation-log.jsonl is **42**. The 403 number is session archives, which is a different metric.
5. **"SWE-bench 80.8% is sinkra's advantage"** — categorically wrong. That's a Claude Code benchmark. Sinkra uses Claude Code, doesn't own the score.
6. **"Self-learning: 20"** — valid at time of writing (2026-04-04), invalidated by Epic-112 Ruflo merge between then and now.

## Automation Need

This revision pass took ~2 hours and touched 4 files. A `bench-analyst refresh` automation (proposed in Epic) would run nightly and:
1. Re-compute all empirical counts via the shell commands documented above
2. Diff against each bench doc's declared numbers
3. Flag drift (>5% delta, or new absolute zeros, or new non-zeros)
4. Post PR comments on PRs that introduce files matching bench scope
5. Generate this REVISION doc as a living append-only record

Without automation, bench docs will continue to drift at the same rate this one did (several weeks of staleness in less than a week of merges). The cost of the manual verification pass was comparable to the cost of running the whole 6way benchmark in the first place — clearly not sustainable.
