# Contrato EP03 → EP04 — F04-1
Entrada: Survey.schema_version=F04-1, projeto_id UUID, hierarquia e cargas identificadas por UUID. API POST /api/v1/levantamentos/validar; PUT /api/v1/local/projetos/{UUID}/levantamento com levantamento e revisao_esperada. GET do projeto/histórico usa API local existente. Persistência aditiva na chave dados.levantamento; preserva modelo F02 e dados legados. Revisão do projeto é a referência histórica. Uma edição marca levantamento_resultados_invalidos=true; cálculos futuros devem comparar conteúdo e revisão de origem. Nenhuma transformação automática para circuitos F02.

Carga ativa tem classe ILUMINACAO/TUG/TUE, quantidade, categoria, tags, origem declarado/estimado, dados de placa e P/Q/S unitários independentes. Arquivados permanecem no histórico e fora dos totais. UUIDs removidos são recusados na gravação; use arquivamento explícito. Filhos ativos exigem pais ativos. Homônimos no mesmo ambiente produzem alerta, sem descartar cargas reais semelhantes.

Saída de consolidação contém total, por_ambiente, por_pavimento e pendencias. Cada grandeza tem valor decimal textual, unidade e cargas_sem_dado. P/Q/S ausentes não são zero conhecido. S é soma aritmética de VA declarados, não magnitude da soma vetorial. Potência de placa e potência atribuída são metadados: não se somam automaticamente a P/S. Quantidade multiplica somente P/Q/S. Nenhuma inferência de corrente, fator, simultaneidade ou demanda é aplicada.

Origem é uma declaração do cadastro; fonte_regra é referência fornecida, sem validação. Conformidade normativa é sempre false; mínimos de pontos permanecem PENDENTE_FONTE_VALIDADA. F05 deve recusar cálculo definitivo com dados insuficientes/inconsistentes e exigir parâmetros e fontes próprias, sem transformar totais parciais em completos.
