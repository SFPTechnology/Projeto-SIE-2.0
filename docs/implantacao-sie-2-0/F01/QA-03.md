# QA-03 — Integração, dados, segurança e UX — F01
Data: 2026-10-15. **Veredito: PENDENTE** para a conclusão integral. Perspectiva crítica de IA, não auditoria independente.

## Artefatos e ensaios
- API `/api/v1/normas/catalogo` e `/api/v1/normas/aplicabilidade` usam `ConfigDict(extra="forbid")`, não aceitam `approved`, `source_verified` etc.; a saída retorna `release_allowed=false`.
- UI `restructuring/apps/web/index.html` e `app.js` mostram painel de catálogo `#normas`, estado não homologado e mensagens em `textContent` (sem renderização de HTML vindo da API).
- `test_web_contract.py` e `restructuring/e2e/test_browser_flow.py` verificam que a UX tem estado pendente; CI Chromium tem ensaio F01 específico.
- A persistência local antiga segue em modo opt-in; **nenhuma migração SQL, secrets ou banco real** tocados.

API consultiva e UX parcial seguras para ambiente local/testes; ainda sem controle de acesso profissional à aprovação, snapshots imutáveis ou autorização de produção. **QA-03 = PENDENTE.**

## Revisão QA-03 — Retomada de 15/10/2026

Mitigação local de QA03-03: `snapshots_normativos` e `eventos_snapshot_normativo` são gravados na mesma transação SQLite dos projetos, com restrição por revisão, triggers contra update/delete e SHA-256. Consultas GET exigem token local e retornam `release_allowed=false`; verificadas por testes de autenticação, revisão conflitante e corrupção proposital de armazenamento.

**ALTA — permanecem:** não existe identidade/autorização multiusuário, snapshots não mostram quais regras/células foram usadas no cálculo, SQLite legado não fornece versões antigas completas, controle de administrador do arquivo supera triggers e não ocorreu migração/ensaio em Postgres/Supabase. A UI ainda não mostra histórico de snapshots, só catálogo. Resultado **QA-03 PENDENTE**, sem aprovação de produção.
